    * Structured the repository with clear directories for different APIs and shared components.
        
    * Managed line endings using `.gitattributes` for consistent cross-platform behavior.
        
3. **Continuous Integration**
    
    * Set up GitHub Actions workflow (`docker-image.yml`) for building Docker images automatically on push/pull requests to the main branch, ensuring continuous integration and testing.
        

### Modular OpenAPI Definition

1. **Split YAML Definitions**
    
    * Divided the OpenAPI specification into multiple, smaller YAML files (`parameters`, `schemas`, `examples`) referenced via `$ref`, promoting reusability and simplifying updates.
        
2. **Sample API Implementation** (GitHub: Update an Issue API)
    
    * Defined clear schema and parameter structures (issue numbers, repository names, etc.).
        
    * Created explicit examples of successful and failed requests/responses.
        
    * Validated with Redocly linter to adhere strictly to OpenAPI 3.0 standards.
        

### Testing and Validation

* **Linting and Validation**:
    
    * Employed Redocly CLI (`redocly lint`) to validate OpenAPI files, ensuring correctness, adherence to standards, and readability.
        
    * Iteratively fixed errors related to schema conformity, unexpected properties, and mandatory fields.
        
* **Dockerfile Testing**:
    
    * Encountered parsing errors due to invisible formatting characters, leading to Docker build failures.
        
    * Resolved by rewriting Dockerfile instructions explicitly in ASCII, demonstrating proactive troubleshooting.

* **Learning Value:** Documenting these endpoints teaches not only OpenAPI syntax, but also best practices in authentication, error handling, and example-driven design.
