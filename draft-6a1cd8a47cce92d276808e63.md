"Performance: Reducing Latency (Kesh) Kesh returns to talk about perceived performance — the real bottleneck wasn't dollar cost, it was latency. There were three inference stages, each adding ~3–4 seconds:

LLM understanding the user's query Executing and converting to schema generator response Generating the schema

Total latency was unacceptably high. They used three techniques to fix it:

1.  "Mostly Generative" approach: About 70% of requests across platforms are predictable/repetitive. For these, instead of creating a separate generative UI skill call, they embedded the predictable UI blocks directly into the parent skill. This cut latency by 70%.
    
2.  Prompt Caching / Pre-warming: A major challenge was agent boot-up time. They used aggressive prompt caching and pre-warming of infrastructure to reduce time-to-first-token by 80%.
    
3.  End-to-End Streaming: Implemented full streaming architecture so responses render as they're generated on the backend. Combined, these three techniques let them use a more powerful model (Claude Sonnet) while still delivering a real-time, snappy experience.""
